# AgentLab Code Review & Remediation Plan

- **Date:** 2026-08-11
- **Reviewed at:** commit `3b12007` (v0.3.0)
- **Method:** Seven subsystem reviews followed by an independent, code-level adversarial review of
  the critical and high findings. This revision incorporates the qualifications, omissions, and
  test-safety issue found during that second pass.
- **Verification:** `go test ./internal/auth ./internal/api ./internal/dashboard` passed. The full
  suite is not green on macOS; see H5 and Test Debt.

> **Safety warning:** Until H5 is fixed, do not run `go test ./cmd/agentlab` or `go test ./...` on
> macOS under a real user home. Those tests can read or mutate the real AgentLab client config.
> Only the targeted packages listed above were rerun safely after discovery.

---

## Verdict

AgentLab has several sound foundations: compare-and-swap state transitions, parameterized SQL,
path traversal defenses, allowlisted and symlink-resolved `sops` execution, and single-use
bootstrap credentials. Those controls do not compensate for the current network authorization
and auxiliary-service boundaries.

The two release-blocking findings are:

1. The TCP control API authenticates callers but does not enforce their command or sandbox scopes.
2. The dashboard defaults to an all-interface listener and exposes a destructive API subset with
   no inbound browser authentication.

The TCP control listener is not wholly unauthenticated: wildcard binding requires a legacy token
and a CIDR allowlist, and SSH-signed tokens must come from an authorized key. The defect is that,
after authentication, declared token restrictions are ignored. The local Unix socket remains a
trusted administrative boundary and needs to keep working without a network token.

The review also found material issues in `/v1/exec`, credential-proxy attachment, background-work
shutdown, resource accounting, timestamp storage, and macOS test isolation. Until C1 is fixed,
disable the nonlocal TCP control listener or limit it to fully trusted, full-access administrators;
an authenticating reverse proxy does not enforce token scopes. Until C2 is fixed, keep the
dashboard loopback-only or place it behind an authenticating, encrypted reverse proxy.

## Critical — fix before any networked deployment

### C1. Scoped API tokens are authenticated but never authorized

- **Files:** `internal/auth/middleware.go:82-110,180-215`, `internal/api/exec.go:112-152`,
  `internal/daemon/api.go:287-312`, `internal/daemon/daemon.go:552-580`
- **Problem:** Authentication stores a `RequestIdentity` in the TCP request context, and
  `IsCommandAllowed` / `IsSandboxAllowed` exist, but production handlers do not call them.
  `/v1/exec` can invoke the full local CLI, while direct REST routes likewise ignore the token's
  command and sandbox claims.
- **Impact:** An authenticated token advertised as restricted can perform operations outside its
  declared scope. Destroying another sandbox is a direct example. `secrets show --reveal` can
  take the local-file path and run with the daemon's filesystem privileges when the daemon account
  has no saved remote endpoint; if that account has an endpoint configured, the command instead
  takes the remote/redacted path. Creating a new wildcard token is possible only when the daemon
  can also read an already-authorized private signing key, so it is not a universal exploit. List
  and bulk routes can leak or affect out-of-scope resources even when no VMID appears directly in
  the URL.
- **Scope-model limitation:** Any holder of an authorized signing key can currently self-issue a
  token containing arbitrary claims. If scopes are intended to restrict signing-key owners, the
  server needs per-key permission ceilings. Otherwise, document scopes explicitly as restrictions
  on delegated bearer tokens rather than RBAC for authorized key owners.
- **Exposure qualification:** Binding to `0.0.0.0` requires both a legacy token and a CIDR
  allowlist (`internal/config/config.go:607-622`). That reduces reachability but does not enforce
  authorization for an authenticated caller.
- **Immediate mitigation:** Disable the nonlocal TCP listener, restrict it to fully trusted
  full-access administrators, or reject scoped identities across the entire network `/v1/*`
  handler chain. Disabling `/v1/exec` removes the broadest command path but does not secure the
  direct REST routes. Do not advertise scoped tokens as enforced until route-level authorization
  exists.
- **Complete fix:**
  1. Keep local Unix requests on an explicitly trusted path, and apply authentication plus
     authorization to a distinct network handler chain. Do not blindly call `FromContext` from
     shared handlers: Unix requests currently have no identity and would fail or panic.
  2. Define typed permissions for every network operation, including create/list/bulk routes.
     Resolve jobs, sessions, and workspaces to their underlying sandbox before checking scope,
     and filter list responses to the caller's permitted resources.
  3. Replace the free-form command string with structured `args []string`; canonicalize aliases
     and global flags before authorization. Prefer typed API routes over parsing CLI text.
  4. Remove the final raw-prefix branch in `Token.IsCommandAllowed`; permit only exact commands
     or an intentional dot-boundary namespace.
  5. If scopes are an RBAC boundary for signing-key owners, store and enforce server-side maximum
     permissions for each authorized key; never trust a signed token to declare its own ceiling.
  6. Add deny-by-default table tests covering each TCP route, indirect resource lookup, list
     filtering, aliases, malformed commands, and trusted Unix behavior.

### C2. The web dashboard has no inbound authentication

- **Files:** `internal/dashboard/server.go:63-106,144-258`,
  `internal/dashboard/static/assets/app.js:12-15`, `cmd/agentlab-dashboard/main.go:43-46`,
  `internal/daemon/daemon.go:552-556`
- **Problem:** The default listener is `:8080`, and `/api/v1/*` routes are registered on an
  unwrapped mux. The configured token is added to outbound Unix-socket requests, but the Unix
  server deliberately has no auth wrapper, so that header is ignored. It does not protect the
  browser-to-dashboard connection.
- **Impact:** Anyone who can reach the dashboard can use its exposed destructive subset: create
  and destroy sandboxes, start jobs, stop all, prune, and manage exposures. The dashboard does
  not expose every daemon operation—secrets, users, integrations, and `/v1/exec` are absent—but
  the available subset is sufficient for major disruption. Missing Origin/CSRF checks also allow
  blind cross-site requests to endpoints that accept simple or empty POST bodies.
- **Fix:**
  1. Default to loopback rather than all interfaces and require an explicit opt-in for remote
     binding.
  2. Require TLS or a documented trusted encrypted tunnel for every non-loopback deployment;
     otherwise bearer credentials and session cookies remain exposed in transit.
  3. Choose an inbound browser-auth design: an authenticating reverse proxy, or a dashboard login
     that exchanges credentials for a secure session. If bearer authentication is retained, the
     frontend must deliberately supply it without embedding a long-lived token in shipped JS.
  4. Do not reuse `ControlAuth.Wrap` unchanged: it only recognizes `/v1/*`, while dashboard routes
     use `/api/v1/*`.
  5. For cookie/session auth, validate Origin and add CSRF protection to state-changing requests.
     Document the trust model and safe Tailscale/reverse-proxy deployment patterns.
  6. Test anonymous rejection, successful authentication, CSRF/Origin failure, and loopback-safe
     defaults.

## High — security, lifecycle, and data-correctness defects

### H1. Remote CLI execution logs secret-bearing arguments; `/v1/exec` streams unsafely

- **Files:** `internal/api/exec.go:42-44,142-150,181-243,300-313`,
  `cmd/agentlab/secrets_remote.go:77-90`, `cmd/agentlab-ssh-gateway/main.go:395-404`
- **Problem:** `/v1/exec` capture and streaming modes and the SSH gateway log raw command
  arguments. Commands such as `secrets set-env --value <secret>` put sensitive values in those
  arguments, contradicting a blanket claim that secrets are redacted from logs. `/v1/exec`
  streaming also has stdout and stderr goroutines write and flush the same `http.ResponseWriter`
  concurrently. The response writer is not safe for concurrent use, and streaming has no total
  output cap. Finally, the API comment says a zero timeout means unlimited execution, while the
  implementation substitutes five minutes.
- **Impact:** Secrets can persist in daemon logs, and concurrent SSE writes can race, interleave,
  or corrupt responses.
- **Fix:** Use structured arguments, prohibit secret values in arguments where possible, and pass
  sensitive values through a non-logged channel. Centralize logging redaction and log only safe
  metadata. Fan stdout/stderr into one writer goroutine, enforce an output limit, and make the
  timeout contract explicit: zero should select a safe server default, and positive client values
  must remain below a server-side maximum. Add race-enabled streaming tests and a regression test
  proving secret values never reach logs in either execution path.

### H2. Detached background operations can outlive shutdown and the database

- **Files:** `internal/daemon/job_orchestrator.go:147-160,738-761`,
  `internal/daemon/api.go:2048-2052`, `internal/daemon/daemon.go:755-772`
- **Problem:** Job execution and other background work use detached `context.Background()`
  goroutines. Direct sandbox provisioning also uses a background context inside an active HTTP
  handler, so it can continue after the server's bounded shutdown window expires. The daemon then
  closes its store without owning and waiting for all such work.
- **Impact:** A process shutdown can leave work running against a closed store and can skip normal
  cleanup after a VM has already been created. Lease GC and startup reconciliation recover many
  expired or partially provisioned sandboxes, so “every interrupted VM is permanent” would be too
  strong. A leftover with no lease expiry, or in a state reconciliation only advances, can remain.
- **Fix:** Give the daemon a lifecycle context and task registry shared by every detached-context
  operation, including synchronous provisioning inside an active HTTP handler—not only explicit
  `go` statements. Registration must close before shutdown waits, avoiding `WaitGroup.Add` versus
  `Wait` races. Shutdown should stop accepting and registering work, cancel the lifecycle context,
  allow bounded cleanup while the store remains open, wait for workers, and close the store last.
  For crash/SIGKILL recovery, define a startup orphan policy with ownership proof, a grace period,
  and an explicit set of states safe to destroy. Test shutdown at each provisioning phase and each
  orphan-policy branch.

### H3. Resource-pool accounting is not a single authoritative lifecycle

- **Files:** `internal/config/config.go:236`, `internal/daemon/daemon.go:422-429,741`,
  `internal/daemon/api.go:2005-2030,3963-3983`,
  `internal/daemon/job_orchestrator.go:641-690`, `internal/daemon/sandbox_alloc.go:26-44`,
  `internal/pool/pool.go:130,163,368`
- **Problem:** Pool limits are disabled by default, but when configured the pool is fresh in-memory
  state attached to manual ControlAPI creation. Normal job-created sandboxes bypass it, and restart
  resets its allocations. Some explicit-VMID error paths fail to release an allocation; auto-VMID
  collision retry can create a sandbox under a different VMID than the allocation key; burst
  reclamation releases accounting before VM destruction is confirmed.
- **Impact:** Capacity enforcement can fail in both directions: bypass/restart permits overcommit,
  while leaked or mismatched allocations cause phantom exhaustion within a daemon lifetime.
- **Fix:** Route every sandbox creation and destruction through one allocation owner. Persist the
  immutable cores/memory allocation snapshot transactionally, or reconstruct it from actual
  backend VM configuration; a sandbox row plus a mutable profile name is not sufficient. Commit
  accounting only for the final VMID, roll it back on every failure, and release it only after
  destruction succeeds. Test manual and job creation, lease GC, job-completion cleanup, collision
  retry, restart, failed destroy, VM-not-found reconciliation, external destruction, and burst
  reclamation.

### H4. Credential proxy accepts unidentified callers and stale sandbox identities

- **Files:** `internal/daemon/integration_proxy_api.go:84-134`,
  `internal/integrations/types.go:83-100`, `internal/db/sandboxes.go:108-126`
- **Problem:** When a source IP is absent from the sandbox database, `auto:all` continues with an
  empty sandbox name and tags, and `MatchesSandbox("", nil)` succeeds. When an IP is present,
  `GetSandboxByIP` does not filter by lifecycle state or lease, so a stale or destroyed row that
  retains an address can still supply a name and tags for named/tagged attachment.
- **Impact:** Any host able to originate traffic from the agent subnet and reach the integration
  proxy can use an `auto:all` credential without being registered. A reused address can also
  inherit credentials attached to the stale sandbox name or tags.
- **Fix:** Reject unidentified source addresses by default. Resolve only a unique sandbox in an
  explicitly eligible live state, validate lease/ownership, and clear or retire IP associations
  during destruction. Make any subnet-wide trust mode a separate, prominently warned setting.
  Test unknown, duplicate, stale, destroyed, expired, and valid sandbox addresses across every
  attachment mode.

### H5. macOS CLI tests can read or mutate the real user configuration

- **Files:** `cmd/agentlab/client_config.go:37-67,108-120`,
  `cmd/agentlab/commands_connect_test.go:16-31,59-89`, `cmd/agentlab/main_test.go:19-28,126-130`,
  `cmd/agentlab/client_config_test.go:41-71`, `cmd/agentlab/ssh_test.go:229-236`,
  `cmd/agentlab/bootstrap_test.go:32-45`, `cmd/agentlab/defaults_commands.go:29-73`
- **Problem:** `clientConfigPath()` uses `os.UserConfigDir()`. On macOS that resolves below
  `$HOME/Library/Application Support` and ignores `XDG_CONFIG_HOME`, while tests isolate only
  `XDG_CONFIG_HOME`. Test setup and cleanup can therefore load, chmod, overwrite, or remove the
  real `agentlab/client.json`.
- **Impact:** Running the test suite can consume a real token, change file permissions, or destroy
  a developer's actual AgentLab client configuration.
- **Review incident:** During this review, a test-looking `client.json` was written under the real
  macOS user-config directory. The artifact and the then-empty `agentlab` directory were removed
  after discovery. Because that location was not inspected before the run, it is not possible to
  rule out a pre-existing configuration having been overwritten or removed; the cleanup may also
  have removed a pre-existing empty directory.
- **Fix:** Inject the client-config path/root in tests. If environment isolation is also tested,
  set both `HOME` and `XDG_CONFIG_HOME` inside a subprocess before any path resolution. Canonicalize
  the resolved path and require it to be below that test's `t.TempDir`; destructive helpers must
  reject any other path. Add a Darwin regression test, audit `defaultsFilePath` as well as client
  config, and establish the invariant that no test may touch the actual user config directory.

## Medium — functional defects and defense in depth

### M1. RFC3339Nano text timestamps are not safely orderable

- **Files:** `internal/db/sandboxes.go:16,512-525` and every database table using `formatTime`
- **Problem:** RFC3339Nano omits or trims fractional digits. SQLite compares the resulting TEXT
  lexicographically, so fractional timestamps within the same second can order incorrectly.
- **Impact:** Expiration, lease, token, and newest-row queries can select the wrong record when
  competing values occur within the same second. No larger cross-second consequence was
  demonstrated, so this is Medium rather than High.
- **Fix:** Adopt either fixed-width UTC nanoseconds or integer Unix nanoseconds, but ship it as a
  schema migration—not a formatter-only change. Inventory every timestamp column, backfill old
  values transactionally, preserve compatible reads during upgrade, and verify mixed-version
  behavior. Add boundary tests for zero, short, and full-width fractional seconds.

### M2. Clone fallback mishandles retry modes and asynchronous failures

- **Files:** `internal/proxmox/api_backend.go:69-94`,
  `internal/proxmox/shell_backend.go:88-108`
- Both backends already retry some synchronous clone failures, so “never triggers” is inaccurate.
  Neither synchronous path checks whether the original request was already a full clone. The API
  backend also does not retry when a linked-clone POST returns a UPID and `waitForTask` later
  reports a storage/snapshot failure.
- **Fix:** Gate both synchronous and asynchronous retry on the original mode being linked. Before
  reposting the same target VMID after a failed UPID, determine whether Proxmox left a partial VM
  or lock; resume, clean up only a positively owned residual target, or fail for operator action.
  Never delete an unrelated existing VM. Wait for the retry UPID and preserve both failures if it
  also fails. Test synchronous and asynchronous failures, residual targets, successful linked
  clone, and an explicitly full clone that must not be retried.

### M3. APIBackend DHCP fallback misses standard Proxmox MAC syntax

- **Files:** `internal/config/config.go:272`, `internal/proxmox/api_backend.go:493,537,1526-1538`,
  `internal/daemon/job_orchestrator.go:283`
- **Problem:** `extractMAC` looks for a `mac=` key, while normal Proxmox network configuration
  embeds the MAC as the value of a model key, for example
  `virtio=BC:24:11:D5:49:57,bridge=vmbr1`. Custom `mac=` input may work, but standard entries do
  not populate the fallback MAC list.
- **Impact:** On the optional API backend, DHCP-lease lookup is skipped for normal configurations,
  leaving guest-agent polling. The shell backend is the default, and IP-not-found is nonfatal
  during provisioning, so this is Medium rather than High.
- **Fix:** Mirror the shell backend's `parseNetMACs`: inspect candidate values regardless of key
  name and validate them with `net.ParseMAC`. Add an end-to-end `APIBackend.GuestIP` test with a
  mocked `/config`, a real lease fixture, and an unavailable guest agent, plus unit cases for
  virtio/e1000 formats, multiple adapters, malformed values, and explicit `mac=` input.

### M4. Dashboard request-body handling permits memory and connection exhaustion

- **Files:** `internal/dashboard/server.go:92-96,159-222`,
  `internal/daemon/integration_api.go:63-67`, `internal/daemon/user_api.go:65-72`
- Body-forwarding routes buffer `io.ReadAll(r.Body)` without a limit and discard read errors.
  GET-only forwarding does not read a body, and the daemon does not universally limit bodies, so
  the original broader claims would be inaccurate. `MaxBytesReader` alone also does not stop
  slow-body connection exhaustion because the dashboard has no `ReadTimeout`.
- **Fix:** Apply endpoint-appropriate caps at every HTTP boundary; daemon user/integration JSON
  handlers should reuse the existing bounded-decoder pattern. Return `413` for oversized bodies
  and `400` for other read failures, configure body/read timeouts, and add bounded concurrency or
  rate limiting where required. Test oversized fixed-length and chunked bodies returning `413`
  without forwarding, injected read errors returning `400`, and slow bodies reaching a bounded
  deadline.

### M5. Integration proxies impose a five-minute total response deadline

- **Files:** `internal/integrations/llm_proxy.go:57-60`,
  `internal/integrations/git_proxy.go:47-50`
- `http.Client.Timeout` covers the complete exchange, including response-body streaming. A single
  LLM stream or Git transfer longer than five minutes is aborted even while bytes are flowing.
- **Fix:** Add daemon-level timeout defaults with optional per-integration overrides, and pass the
  resolved policy through `ProxyHandlerOptions`. For legitimate streaming or long transfers, rely
  on request-context cancellation plus explicit connect, response-header, and response-body idle
  deadlines—not `Transport.IdleConnTimeout`, which only controls pooled idle connections. With a
  fake clock or short test durations, prove that an actively flowing stream can exceed the old
  total limit, a stalled body is terminated, and downstream cancellation reaches the upstream.

### M6. Tag-based integration attachment is incomplete end to end

- **Files:** `internal/db/sandboxes.go:65-84`,
  `internal/daemon/api_types.go:234,303-316,371-389`, `cmd/agentlab/api.go:186`
- `CreateSandbox` omits the tags column, but persistence is only one gap: control API request and
  response types, job/validation producers, and the CLI creation path do not expose tags, and
  there is no update lifecycle.
- **Fix:** Define tag behavior for direct, job-created, and validation-plan sandboxes. Normalize by
  trimming, rejecting invalid values, choosing and documenting case sensitivity, and deduplicating
  in stable order. Define updates as full replacement, or expose a separately named merge
  operation. Persist tags transactionally, expose them through API and CLI, return them in
  responses, and test creation through proxy matching.

### M7. SSH gateway timeout and host-key controls are incomplete

- **Files:** `cmd/agentlab-ssh-gateway/main.go:62,101,160,233-267,650-657,708-733`
- `--idle-timeout` is parsed and logged but never enforced. Keepalives detect some dead peers, but
  idle live sessions remain unlimited. Connections to sandboxes use
  `ssh.InsecureIgnoreHostKey()`, so a host reusing an agent-subnet address can impersonate the
  target. If the gateway server host key is missing, an ephemeral key is generated but not
  persisted, despite documentation implying stable auto-generation.
- **Fix:** Enforce activity-aware idle deadlines, pin sandbox host keys to VM identity with an
  explicit rotation flow, and atomically persist generated gateway keys with mode `0600`. Tests
  should prove that bidirectional activity resets the idle deadline, generated gateway identity
  survives restart, and VM recreation follows the declared host-key rotation policy.

### M8. Bare remote endpoints silently select plaintext HTTP

- **Files:** `cmd/agentlab/client_config.go:160-186`, `cmd/agentlab/api.go:688-695`,
  `cmd/agentlab/init.go:203-208`, `README.md:328-336`
- Bare `host:port` input is normalized to `http://`, after which bearer credentials are attached.
  This is not a protocol downgrade from an existing TLS connection, and `agentlab init` emits an
  explicit `http://` URL. The supported topology intentionally uses HTTP inside Tailscale because
  the daemon has no native TLS listener.
- **Fix:** Require an explicit scheme consistently for CLI flags, environment variables,
  bootstrap/connect output, and both new and legacy saved configuration. Warn or require an
  `--allow-insecure-http` acknowledgement for non-loopback HTTP outside a documented trusted
  tunnel, and define whether that acknowledgement is one-shot or persisted. Do not default to
  HTTPS until the server or documented reverse-proxy path supports it.

### M9. Free-form command tokenization breaks quoted arguments

- **Files:** `internal/api/exec.go:309-313`, `cmd/agentlab-ssh-gateway/main.go:429-434`
- `strings.Fields` treats quotes as ordinary characters and cannot preserve argument boundaries,
  so `--task "fix the flaky test"` does not provide CLI parity. The same bug exists in the SSH
  gateway command path.
- **Fix:** Make `args []string` the canonical HTTP transport. Standard SSH `exec` carries only a
  command string, so the gateway must either use a documented non-executing lexer or introduce a
  custom encoded-argv convention. In both cases, pass canonical argv directly to
  `exec.CommandContext`, never through a shell, and authorize only after canonicalization. Test
  empty arguments, spaces, escapes, malformed quotes, and the absence of shell expansion.

## Test debt and low-severity cleanup

- **Recovery and asynchronous Proxmox coverage:** `ReconcileState`
  (`internal/daemon/sandbox_manager.go:1169-1238`) has no direct branch coverage, and API backend
  mocks return no UPID, leaving task `exitstatus` failures untested. Add UPID polling tests plus
  `ErrVMNotFound`, stopped-RUNNING, and provisioning-step reconciliation cases. New Proxmox tests
  must use fake backends, `httptest`, or recorded fixtures by default. Any live-host test must have
  a separate build tag, explicit environment opt-in, reserved VMID/storage ranges, and guaranteed
  cleanup.
- **Meaningless state-transition assertions:** `internal/models/models_test.go:274-319` passes the
  destination state as a testify message argument, so the tests assert nothing useful. Do not call
  the unexported sandbox `allowedTransition` from the models package. Move authoritative sandbox
  transition tests beside `internal/daemon/sandbox_manager.go:1098-1124` and cover both allowed and
  denied edges. Jobs currently have no transition validator—`UpdateJobStatus` accepts any nonempty
  status—so either introduce centralized job-transition enforcement before testing it or delete
  the misleading job transition map.
- **Timing-dependent tests:** Only the daemon lifecycle sleeps are startup synchronization that
  should become readiness polling. In the dashboard test, the fake daemon's Unix listener is
  already bound before the 50 ms wait; the workspace test's 150 ms wait deliberately delays lease
  release. Replace each with the appropriate event/barrier rather than one generic polling fix.
- **macOS portability:** The full suite also encounters Unix-socket paths longer than Darwin's
  limit (`internal/daemon/daemon_test.go:42-47`, `tests/integration_test.go:40-51`,
  `cmd/agentlab/commands_daemon_test.go:22-30`) and `/tmp` versus `/private/tmp`
  symlink-resolution expectations (`internal/secrets/bundle_test.go:137-151`,
  `internal/secrets/bundle.go:356-359`). Use a short, test-owned socket root and compare
  canonicalized paths.

Missing tests are important risk multipliers, but are not themselves runtime defects and therefore
are not classified as High findings.

## Recommended sequencing

1. **Install immediate guardrails:** isolate client-config tests, bind the dashboard to loopback by
   default, and disable the nonlocal TCP control listener or reject scoped identities across its
   complete `/v1/*` chain. Disable network `/v1/exec` even for full-access identities unless its
   broader execution risk is explicitly accepted.
2. **Restore a safe verification baseline:** fix H5 and the remaining macOS portability failures,
   then make the hermetic full suite a release gate before undertaking migrations or lifecycle
   refactors.
3. **Implement the network authorization boundary:** C1, C2, exact command matching, resource
   resolution, filtered list behavior, and the HTTP structured-argv half of M9. Keep network exec
   disabled until H1 and that canonicalization work are complete.
4. **Harden execution and credentials:** H1 and H4, including log-redaction, stream serialization,
   source-identity, and IP-reuse tests.
5. **Own daemon lifecycle and capacity state:** H2 and H3, with shutdown, crash, restart, and
   failure-path tests.
6. **Migrate timestamp storage:** M1 with a schema-versioned backfill and compatibility tests.
7. **Repair backend behavior:** M2 and M3 using mocked or recorded Proxmox payloads—not a live
   endpoint by default.
8. **Finish auxiliary hardening and feature plumbing:** M4-M8 and the SSH half of M9, including
   body limits, tag lifecycle, SSH controls, and streaming deadline configuration.

Every critical and high item above is grounded in the reviewed commit. Where the initial review
used categorical language or proposed an incomplete fix, this revision records the narrower claim
and the additional work required for a complete remediation.
